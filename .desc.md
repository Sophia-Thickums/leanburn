Operation: Lean Burn - a cost doctrine for long agent sessions on metered inference budgets.

Lean burn is the engine principle of running on excess air: less fuel for the same power.
The engine runs leaner, not idler. Applied to token spend, the same idea does the same work,
on the same model, for a fraction of the bill - by changing how the session is SHAPED rather
than by shrinking what the session does.

The finding that makes it possible: modern API pricing has two levers, and they are not equal.
Cached input re-reads a stable prefix at a small fraction of the full input rate (on DeepSeek
V4.1-Flash, $0.003/1M cached vs $0.15/1M uncached off-peak - a 50x spread on identical
tokens), and peak hours bill at exactly double (DeepSeek peak = Mon-Fri 01:00-04:00 and
06:00-10:00 UTC; everything else including all weekend is off-peak).

Most of a long session's input is cache-eligible, because the same prefix is re-sent every
turn. So the dominant term in the bill is not how much the agent thinks. It is whether that
prefix stays cacheable, and when the work runs.

Nine laws, each earned by measurement:
  1. Keep the prefix stable - the cache is the whole game.
  2. Read by address, never by inhaling whole files for one fact.
  3. One decisive spend per 24h, not dribble across the day.
  4. Batch tool calls into one round trip instead of ten.
  5. Run heavy work off-peak.
  6. Auxiliary routes belong on the same model as the main route - compare CACHED rates.
  7. Never trim what the agent IS; trim the plumbing.
  8. A cap is a guard rail, not a muzzle.
  9. Measure with a meter, never with a feeling.

Included: src/meter.py, a read-only ledger reader that prices per-session token counters at
the correct rate for the hour the work happened - reporting cache-hit ratio, the cold-cache
equivalent, and the effective saving. It makes no network calls, and anything it cannot price
is labeled unpriced rather than guessed. Run `--selftest` to verify the arithmetic first.
